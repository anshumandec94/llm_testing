# Simulation Playground — Architecture & Planning

## Overview

This repo tests whether LLMs (and transformer-based models) can act as reliable, verifiable simulators for agent-based recommender system evaluation. We use MovieLens-32M as the fixed use-case and compare four agent types under a shared simulation harness.

## Three Core Pieces

### 1. Environment (`sim/environment.py`)

Responsible for all data loading, splitting, and embedding generation.

**Initialisation steps:**
1. Load `ratings.csv`, `movies.csv`, `movie_overviews.csv` from `data/ml-32m/`.
2. **Hold-out split**: for a configurable subset of users (`eval_user_frac`), hold out a configurable fraction of their most-recent ratings (`holdout_frac`). These are the ground-truth positives for evaluation.
3. Expose `train_ratings` (all ratings minus held-out), `held_out` (dict of userId → ItemList), and `all_movies` metadata.
4. **Associative embeddings (MF)**: train a `BiasedMFScorer` on `train_ratings` via LensKit and expose the learned user-factor matrix and item-factor matrix via ChromaDB. Collection name: `associative_item_factors`.
5. **Semantic embeddings**: encode each movie's `title + genres + overview` string with `sentence-transformers` and persist in ChromaDB. Collection name: `semantic_movie_embeddings`.
6. **Embedding persistence**: ChromaDB is stored at `embeddings/chroma/`. If the collection already exists and `force_rebuild=False`, skip re-encoding.

**Key attributes exposed to other components:**
- `dataset`: LensKit `Dataset` built from `train_ratings` (used to train the recommender).
- `held_out`: `dict[int, ItemList]` — per-user held-out items.
- `eval_users`: list of user IDs in the evaluation subset.
- `movie_meta`: DataFrame with `movieId`, `title`, `genres`, `overview`.
- `chroma_client`: shared ChromaDB client.

---

### 2. Recommender (`sim/recommender.py`)

A thin wrapper around a **LensKit 2026** top-N pipeline.

- Default algorithm: `BiasedMFScorer` (ALS matrix factorisation, 64 latent factors).
- Exposes `train(dataset)`, `recommend(user_id, n, candidates)` → `ItemList`.
- Maintains an **internal user-state** as a running partial re-fit or score adjustment (v0: retrain on updated ratings, v1: incremental update).
- The recommender's view of the user is intentionally imperfect — it only sees the training ratings plus any feedback collected during simulation, not the agent's internal model.

---

### 3. Agents (`sim/agents/`)

All agents share the `AbstractAgent` interface (see `base.py`):

```python
class AbstractAgent:
    def evaluate(self, candidates: ItemList, user_id: int) -> ItemList:
        """Return candidates re-ranked with a `score` field."""
    def update(self, feedback: ItemList) -> None:
        """Incorporate accepted recommendations as new observations."""
```

#### Agent 1 — Associative (`associative.py`) ✅ *implemented*
- Retrieves the user's latent factor vector from the ChromaDB `associative_item_factors` collection (stored at environment initialisation).
- Scores each candidate by cosine similarity between the user vector and the candidate's item vector.
- No LLM or semantic model required; runs fully offline.

#### Agent 2 — Semantic (`semantic.py`) 🔲 *stub*
- Maintains a running centroid of the semantic embeddings of movies the user has rated highly (≥ 4.0).
- Scores candidates by cosine similarity to that centroid.
- Uses the `semantic_movie_embeddings` ChromaDB collection.

#### Agent 3 — Seq2Seq (`seq2seq.py`) 🔲 *stub*
- Based on SASRec (Self-Attentive Sequential Recommendation).
- Encodes the user's rating sequence and scores candidates via the model's next-item probability.
- Reference: https://github.com/kang205/SASRec

#### Agent 4 — LLM (`llm.py`) 🔲 *stub*
- Uses an LLM (local via `mlx-lm`, or API) as the reasoning engine.
- Retrieves relevant memories (past liked/disliked movies) from ChromaDB as context.
- Constructs a prompt asking the LLM to score/rank the candidate list.

### Simulation Runner (`sim/runner.py`)

Orchestrates one full experiment run.

```
for round in range(num_rounds):
    for user in eval_users:
        candidates = recommender.recommend(user, n=k)
        ranked     = agent.evaluate(candidates, user)
        accepted   = ranked.top_n(accept_k)           # agent "watches" top-k
        agent.update(accepted)
        recommender.update_user(user, accepted)        # feedback loop
        log metrics to MLflow
```

**MLflow integration:**
- Each experiment is one `mlflow.start_run()`.
- Parameters logged: agent type, num_rounds, k, accept_k, eval_user_frac, holdout_frac, recommender algorithm.
- Per-round metrics: `ndcg@k`, `hit_rate@k`, `holdout_recall` (fraction of held-out items surfaced so far).
- Artifacts: recommendation lists per round (Parquet), final metric summary CSV.

---

## Evaluation Protocol

1. Hold-out a subset of ratings **before** any simulation begins.
2. Run `num_rounds` of simulation where the recommender generates candidates outside the user's known history (including held-out items if they haven't appeared yet).
3. Track where held-out items appear in recommendation lists across rounds (`holdout_recall`).
4. Compare across agent types using the same random seeds, same hold-out set, and same recommender.

## Configuration (`sim/config.py`)

All hyperparameters live in `SimConfig`:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `data_dir` | `data/ml-32m` | Path to ML-32M CSVs |
| `embeddings_dir` | `embeddings/chroma` | ChromaDB persistence path |
| `mlflow_tracking_uri` | `mlruns` | Local MLflow directory |
| `experiment_name` | `abm-recsys` | MLflow experiment name |
| `eval_user_frac` | `0.05` | Fraction of users in eval set |
| `holdout_frac` | `0.2` | Fraction of each eval user's ratings held out |
| `min_ratings` | `50` | Minimum ratings for a user to be eligible |
| `num_rounds` | `10` | Simulation rounds |
| `rec_list_size` | `20` | Recommendations per round (k) |
| `accept_k` | `5` | Items the agent "accepts" per round |
| `mf_features` | `64` | Latent factors for BiasedMF |
| `semantic_model` | `all-MiniLM-L6-v2` | Sentence transformer model |
| `random_seed` | `42` | Global random seed |
| `force_rebuild_embeddings` | `False` | Re-build ChromaDB even if it exists |
